## Commands

```bash
# Development
npm run dev          # Start Vite dev server

# Build & Type Check
npm run build        # tsc -b && vite build

# Lint
npm run lint         # ESLint across the project

# Tests
npm test             # Vitest in watch mode
npm run test:run     # Run tests once (CI)
npm run test:coverage  # Coverage report via v8
```

To run a single test file:
```bash
npx vitest run src/__tests__/App.test.tsx
```

## Architecture

This is a **single-page React portfolio** (Vite + TypeScript + Tailwind CSS). There is no routing — the page is one long scroll through section components.

### Data flow

All portfolio content lives in a single source of truth: `src/data/portfolio.ts`. It exports typed arrays (`personalInfo`, `experience`, `education`, `certifications`, `projects`, `skills`). Every section component and the chatbot engine read from here. **Adding or editing content means editing this file only.**

### Provider hierarchy (`App.tsx`)

```
<LanguageProvider>       ← i18n context (EN/FI), translations live inline in LanguageContext.tsx
  <ThemeProvider>        ← dark/light/system, persisted in localStorage under 'portfolio-theme'
    <SEO />
    <Header />
    <main> sections... </main>
    <Footer />
    <Chatbot />          ← floating overlay, independent of section order
  </ThemeProvider>
</LanguageProvider>
```

### i18n

UI strings are translated via `useTranslation()` (wraps `useContext(LanguageContext)`). Translation keys and Finnish/English strings are all colocated in `src/contexts/LanguageContext.tsx`. Portfolio data itself (job descriptions, project names, etc.) is **not** translated.

### Chatbot

`src/lib/chatbot-engine.ts` is a pure keyword-matching engine — no external API. It imports directly from `src/data/portfolio.ts` and returns Markdown-formatted strings. `src/components/Chatbot.tsx` renders the UI. To extend its vocabulary, add keyword arrays and handler functions inside the engine file.

### UI primitives

The project uses **shadcn/ui** components (Radix UI primitives + Tailwind). Component source is in `src/components/ui/` (not shown in tree above but generated by shadcn). The `@` alias resolves to `src/`.

### Testing

- Framework: **Vitest** + **React Testing Library** in a jsdom environment
- Setup file: `src/test/setup.ts` — mocks `localStorage`, `matchMedia`, `IntersectionObserver`, `ResizeObserver`, `scrollIntoView`, `scrollTo`
- Tests go in `src/__tests__/` (App-level) or `src/components/__tests__/` (component-level)
- Use `customRender` from `src/test/utils/test-utils` when a component needs `LanguageProvider`/`ThemeProvider`

### Deployment

Deployed to Vercel (`vercel.json` present). Analytics via Plausible, injected dynamically in `App.tsx` using the current hostname as the tracking domain.
